# EmpathLLaMa

### Локальный AI-собеседник, который умеет сначала услышать

**EmpathLLaMa** — исследовательский проект локального русскоязычного AI-собеседника для бережного разговора о чувствах. В основе лежит `Qwen2.5-7B-Instruct`, дообученная LoRA-адаптером на эмпатичных диалогах и синтетических примерах терапевтической рефлексии.

Проект объединяет ML-пайплайн, локальный inference core, FastAPI-бэкенд, память диалога, кризисные guardrails и адаптивный веб-интерфейс в стиле современных AI-чатов.

> EmpathLLaMa не пытается немедленно «починить» человека списком универсальных советов. Её основной паттерн — признать переживание, уточнить контекст и помочь пользователю внимательнее услышать себя.

## Возможности

- локальная языковая модель без передачи диалогов внешнему LLM API;
- естественный русскоязычный диалог с сохранением контекста;
- LoRA-адаптер поверх `Qwen2.5-7B-Instruct`;
- отдельные пользовательские сессии;
- кризисный фильтр до обращения к модели;
- FastAPI REST API с автоматической OpenAPI-документацией;
- адаптивный интерфейс для компьютеров и телефонов;
- светлая и тёмная темы;
- локальная история разговоров в браузере;
- лёгкий demo-провайдер для разработки UI без загрузки модели.

## Как выглядит диалог

**Пользователь**

> Мне предстоит важное выступление перед публикой, и я боюсь опозориться.

**EmpathLLaMa**

> Понимаю, насколько тяжело выходить к людям с ощущением, будто любая ошибка станет заметна всем. Когда ты представляешь это выступление, что именно для тебя означает «опозориться»?

Цель такого ответа — не обесценить тревогу готовой инструкцией, а сначала признать её и найти личный смысл переживания.

## Быстрый старт

### 1. Подготовьте окружение

Рекомендуется Python 3.11.

```bash
python3.11 -m venv venv311
source venv311/bin/activate
pip install --no-cache-dir -r requirements.txt
```

### 2. Запустите приложение

```bash
uvicorn front_back.backend.main:app \
  --host 127.0.0.1 \
  --port 8000
```

После запуска доступны:

- веб-интерфейс: <http://127.0.0.1:8000>;
- Swagger UI: <http://127.0.0.1:8000/docs>;
- проверка состояния: <http://127.0.0.1:8000/api/health>.

Для разработки интерфейса веб-приложение использует лёгкий `MockModelRunner`. Он сохраняет тот же контракт, что и ML-core, поэтому фронтенд и API можно разрабатывать без расхода VRAM. Провайдер находится в `front_back/backend/model_upp.py`.

## ML-core

### Базовая модель

В качестве основы используется `Qwen2.5-7B-Instruct`. Модель выбрана за сильное понимание русского языка, устойчивое следование инструкциям и достаточно компактный размер для локального запуска с квантованием.

### Параметры LoRA

| Параметр | Значение |
|---|---:|
| Base model | `Qwen/Qwen2.5-7B-Instruct` |
| Метод | PEFT / LoRA |
| Rank | `16` |
| Alpha | `32` |
| Dropout | `0.05` |
| Target modules | `q_proj`, `k_proj`, `v_proj`, `o_proj` |
| Task type | Causal Language Modeling |
| Итоговый loss | около `0.7` |

LoRA изменяет только небольшой набор дополнительных матриц, поэтому адаптер занимает значительно меньше места, чем полный checkpoint модели. Веса проекта находятся в `my_psychologist_final/`.

### Inference pipeline

Обработка одного сообщения проходит последовательно:

1. API валидирует `session_id` и текст сообщения через Pydantic.
2. Guardrails проверяют вход на признаки кризисной ситуации.
3. Сообщение добавляется в контекст соответствующей сессии.
4. Системный промпт и история собираются в единый model input.
5. Qwen генерирует продолжение с подключённым LoRA-адаптером.
6. Внутренняя часть ответа отделяется от пользовательского текста.
7. Ответ сохраняется в память и возвращается фронтенду.

Для экономии памяти `ModelRunner` поддерживает 4-bit NF4-квантование, ограничение длины входного контекста и перенос части слоёв между GPU и CPU.

## Обучающий пайплайн

### Данные

Основой корпуса стали диалоги о психологических переживаниях и пользовательские истории. Перед обучением данные проходят очистку, дедупликацию и фильтрацию слишком коротких, повреждённых или смешанных по языку примеров.

### CoT-дистилляция

Для синтетического расширения корпуса использовалась teacher-модель. Она формировала пример в два этапа:

1. анализировала эмоции, контекст, возможные когнитивные искажения и скрытые потребности;
2. создавала короткий эмпатичный ответ с одним открытым вопросом.

Такой формат помогает student-модели не перескакивать сразу к советам и поддерживать исследовательский диалог.

Во время экспериментов высокая температура приводила к межъязыковому загрязнению текста. Рабочий диапазон `0.65–0.70` сделал русскоязычные примеры заметно стабильнее.

## Безопасность

Психологический диалог относится к чувствительной области, поэтому проверка безопасности выполняется **до** генерации модели.

При обнаружении признаков угрозы жизни или самоповреждения:

- inference блокируется;
- контекст сессии очищается;
- пользователь получает отдельное кризисное сообщение;
- интерфейс визуально выделяет такой ответ.

Текущий keyword-based guardrail — первый защитный слой. Для публичного продукта его следует дополнить отдельным классификатором риска, локализацией экстренных контактов и ручной оценкой критических сценариев.

## Конфиденциальность

- ML-core рассчитан на локальный запуск;
- фронтенд не использует сторонние аналитические сервисы;
- история интерфейса хранится в `localStorage` браузера;
- серверная память сессий очищается при перезапуске процесса;
- сообщения не записываются в базу данных и логи приложения.

Перед публичным развёртыванием необходимо добавить политику хранения данных, авторизацию, шифрование и явное согласие пользователя.

## Системные требования

### Web demo

- Python 3.11;
- 1 ГБ свободной RAM;
- современный браузер;
- GPU не требуется.

### Локальный ML inference

- Linux;
- NVIDIA GPU с CUDA;
- рекомендуется от 8 ГБ VRAM для комфортного запуска 7B-модели;
- 16 ГБ RAM или больше;
- актуальный NVIDIA driver;
- место для базовой модели и Hugging Face cache.

На GPU с меньшим объёмом VRAM можно использовать более сильное квантование или вынести часть слоёв на CPU, пожертвовав скоростью генерации.
